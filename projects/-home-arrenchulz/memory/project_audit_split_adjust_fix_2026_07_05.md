# Audit split-adjust fix — PR #474 (2026-07-05)

`tools/data_integrity_audit.py` recomputed price-derived features from the RAW
`production_data/price_history.csv`, but the features use split-adjusted prices. Any ticker
with a split in the trailing 252d window false-flagged `STALE_MISMATCH` (post-split price vs
pre-split high). **MLTX** (10:1 forward split 2025-09-29): stored drawdown −14.5% (correct),
audit recompute −69.4% (raw) → false FAIL flagged daily, with a *dangerous* root_cause
recommendation to overwrite the correct stored value with the raw one.

**Fix:** added `_split_adjust_prices(prices, as_of, registry)` — applies
`corporate_actions.json` factors via `common.corporate_actions.cumulative_split_factor`
before recompute. Narrow (only in-window split tickers change; rest byte-identical),
fail-open on empty registry. Also added repo-root to `sys.path` (script's first
repo-internal import; runs as subprocess in daily pipeline). Rejected the naive "point
audit at `price_history_split_adj.csv`" — that file is built by standalone
`repair_price_history_splits.py`, NOT regenerated by the daily refresh, so it lags.

Validated on 2026-07-03: MLTX FAIL→OK. 45 tests (4 new) + 82 regression pass; ruff clean.
Done in isolated clone `~/biotech_mltx_fix` (shared checkout never touched). Commit
`30412bc2`, **PR #474 open** (base main). Uncovered a separate feature bug —
see [[project-2026-forward-splits-unadjusted]].
