Do not create a canonical artifact whose primary purpose is to manufacture evidence that a
governance step (a "cycle", a checklist item, a sign-off) occurred. That is governance theater,
not durable knowledge, and it silently corrupts the thing the gate exists to protect.

**Why:** during [[project_pkos_m2_activation_2026_07_17]] Item 9 (requires ≥3 independent manual
promotion cycles), the assistant proposed a same-day "Cycle 2" using a purpose-built
`docs/M2-CYCLE-LOG.md` file whose main content was the log of the cycles themselves. The user
rejected it: creating content just to prove a cycle happened is artificial progress, and doing it
same-day also defeated the actual point of requiring 3 *separate-occasion* cycles — testing the
workflow across different operating conditions so one unnoticed environment/process defect can't
contaminate all three.

**How to apply:** when a task requires N repetitions/instances of something as evidence (test
runs, promotion cycles, review cycles), each instance must be genuine and, where independence
across time/conditions is the stated point, must not be satisfied by repeating within one sitting.
If no genuine instance is available yet, report the gate as still open rather than inventing one.
Never edit a checklist/status document to mark a gate passed when the underlying evidence doesn't
independently exist — say so plainly and stop.
